{# Live password-length feedback for the three screens that SET a password. Deliberately not the HTML `minlength` attribute: that produces the browser's own native validation bubble, which is OS-styled, unstyleable, and appears nowhere else in EdgeCase. Reported by Rick 2026-08-09 after it shipped on the recovery reset screen. Also deliberately not a modal. EdgeCase does use custom modals for validation that interrupts an action (see showAiScribeValidationMessage), but inline field feedback is what login.html and change_password.html already do with their server-rendered .error / .error-message div, and a modal for "keep typing" would be heavier than the problem. Server-side validation in auth.py remains the authority — this only tells the user sooner. Usage: {% with field_id='new_password', confirm_id='confirm_password' %} {% include 'components/_password_policy.html' %} {% endwith %} confirm_id is optional; when given, the match check is included too. #}
